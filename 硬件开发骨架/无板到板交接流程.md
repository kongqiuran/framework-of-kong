# 骨架：无板到板交接流程

> 适用于：需要实物验证的硬件/FPGA/嵌入式项目。
> 
> 核心思想：**实物不在时做准备，实物到了按手册执行。每一步都有门禁。**

---

## 两大阶段

```
┌─────────────────────────────────────────────────────────────┐
│                    阶段一：无板准备                           │
│  （实物暂不可用时，继续完成可离线做的所有工作）                │
└─────────────────────────────────────────────────────────────┘
    ↓
    ├── 资料核对（数据手册、原理图、引脚表）
    ├── 候选设计（通用 RTL、候选顶层、候选 XDC）
    ├── 仿真验证（testbench、行为模型）
    ├── 综合准备（时序约束、资源评估）
    ├── 测试方案（验证步骤、预期结果、失败判据）
    └── 到板手册（供实物到了后独立执行）
    ↓
    所有产物标记为：CANDIDATE / ASSUMPTION / HW-PENDING
    ↓
┌─────────────────────────────────────────────────────────────┐
│                    阶段二：到板执行                           │
│  （实物到了后，按手册逐项执行和验证）                         │
└─────────────────────────────────────────────────────────────┘
    ↓
    ├── 完全断电检查与通断
    ├── 各板独立限流供电
    ├── 电源和共地实测
    ├── 用户逐项确认接线
    ├── 安全静态 IO / JTAG
    ├── 关键握手与数据波形
    └── 已知安全输入验证
    ↓
    每步通过后才能标记对应门禁状态
```

---

## 阶段一：无板准备清单

### 必须完成

| 任务 | 产物 | 状态标记 |
|-----|------|---------|
| 确认完整型号和版本 | 型号记录 | ASSUMPTION |
| 核对电源、逻辑电平、接地 | 电气参数表 | ASSUMPTION |
| 建立候选逐针接线表 | 接线表（含信号方向、默认电平） | CANDIDATE |
| 编写通用 RTL | 与物理管脚无关的参数化代码 | SIM-PENDING |
| 编写 testbench | 正式仿真用 | SIM-PENDING |
| 生成候选 XDC/约束 | 供文本检查和对照 | CANDIDATE |
| 写到板手册 | 独立可执行文档 | DOC-PASS |

### 禁止事项

- 不得把候选文件称为最终结论
- 不得生成最终 XDC、可上板 bitstream 或标记 HW-PASS
- 不得用无板仿真结果替代真实硬件验证

---

## 阶段二：到板执行清单

### 门禁顺序（必须依次解锁）

```
C01 硬件事实与安全确认
    → 解锁：C02 接线与约束

C02 接线与约束
    → 解锁：C03 最小功能验证

C03 最小功能验证（ADC采样/基本通信）
    → 解锁：C04 触发与缓存

C04 触发与缓存
    → 解锁：C05 DMA/数据通路

C05 DMA/数据通路
    → 解锁：C06 网络与主机显示

C06 网络与主机显示
    → 解锁：C07 校准与测量
```

### 整关批量执行

- 当前关卡解锁后，**一次性给出完整操作清单**
- 包含：前置条件、全部操作、判定标准、停止条件、结果模板
- 用户按清单连续完成，不需要每步回复
- 只有出现 FAIL / UNKNOWN / 异常才中途停止

---

## 证据与门禁状态

| 状态 | 含义 | 谁能标记 |
|-----|------|---------|
| `HW-PENDING` | 等待实物验证 | 任何阶段 |
| `SIM-PASS` | 仿真通过 | 无板阶段 |
| `SYNTH-PASS` | 综合通过 | 无板/到板 |
| `TIMING-PASS` | 时序通过 | 到板后 |
| `HW-PASS` | 真实硬件验证通过 | 到板后，有实物证据 |

---

## 到板手册必备内容

每个步骤至少写明：
1. 步骤编号与目标
2. 前置条件和准入门槛
3. 需要用户执行的唯一当前操作
4. 这样做的原理与准确资料来源
5. 输入与输出、信号方向、默认/有效状态
6. 预期现象与测量方法
7. 异常表现
8. 立即停止条件
9. 恢复或回退方式
10. 需要保存的证据及命名方式

---

## 裁剪建议

| 项目类型 | 建议做法 |
|---------|---------|
| 纯仿真/验证项目 | 不需要到板流程，只保留 SIM-PASS |
| 开发板 + 标准模块 | 使用标准流程，但可跳过部分安全门禁 |
| 定制硬件/自研板 | 严格流程，每个门禁独立验证 |
| 教学/学习项目 | 简化到板手册，保留核心安全步骤 |
