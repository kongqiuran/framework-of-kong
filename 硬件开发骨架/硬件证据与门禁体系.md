# 骨架：硬件证据与门禁体系

> 适用于：涉及实物硬件、电气连接、FPGA 下载、仪器测量的项目。
> 
> 核心思想：**没有可追溯证据的结论，等于没有结论。**

---

## 证据等级

| 等级 | 类型 | 可信度 | 示例 |
|-----|------|-------|------|
| L0 | 口头/记忆 | 最低 | "我记得上次是这样的" |
| L1 | 用户口述 | 低 | 用户说"已经接好了" |
| L2 | 文档引用 | 中 | 数据手册第 X 页 |
| L3 | 照片/截图 | 中高 | 接线照片、ILA 截图 |
| L4 | 仪器测量 | 高 | 示波器波形、万用表读数 |
| L5 | 可复现测试 | 最高 | 已知输入下的稳定输出 |

## 门禁规则

### 通用原则

1. **不得跳过基本硬件安全**
   - 不并联未经证明可并联的电源
   - 不把高于 IO 允许范围的电压接入数字 IO
   - 不带电使用电阻/蜂鸣档
   - 未知输入不进行首次联调

2. **逐针确认原则**
   - 最终接线结论必须经用户确认
   - 无板时的候选接线表 ≠ 最终接线结论

3. **JTAG 优先原则**
   - 初次联调先用 JTAG 临时下载
   - 确认时序和数据正确后，才考虑 QSPI 固化

4. **分级上电原则**
   - 完全断电 → 各板独立限流供电 → 电源和共地实测 → 逻辑验证

### 状态管理

```
无板阶段可取得：
    DOC-PASS（文档审查通过）
    SIM-PASS（仿真验证通过）
    SYNTH-PASS（综合通过）

到板后可取得：
    TIMING-PASS（带真实约束的时序通过）
    HW-PASS（真实硬件验证通过）

注意：SIM/SYNTH 不能关闭 HW-PENDING
```

## 资料冲突处理

当数据手册、原理图、模块规格书之间存在冲突时：

1. 显式记录冲突点
2. 说明采用某一来源的理由
3. 标记为 `ASSUMPTION / PENDING-VERIFY`
4. 到板后优先验证该假设

---

## 用户声明 vs 环境复现

- 用户报告 `Cxx PASS` → 记录为 `USER-DECLARED PASS`
- 没有测量值/照片/工具输出 → 同时标记 `EVIDENCE-WITHHELD`
- 当前环境不能复现 → 保留用户报告，明确记录差异

## Git 与证据绑定

每个门禁对应可复查的 Git 状态：

```
1. 保存 HEAD、工具版本、命令、配置
2. 只暂存该门禁相关文件
3. 形成聚焦提交（一个提交 = 一个门禁）
4. 提交信息包含门禁状态和证据文件名
```

## 裁剪建议

| 项目类型 | 证据要求 |
|---------|---------|
| 软件仿真 | L2（文档）+ L3（截图）即可 |
| 开发板标准实验 | L3（照片）+ L4（基本测量） |
| 工业生产/交付 | L4（仪器）+ L5（可复现测试）全部 |
| 高压/大电流/运动设备 | 增加隔离、放电、限流、急停证据 |
