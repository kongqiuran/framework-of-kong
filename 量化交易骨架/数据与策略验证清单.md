# 骨架：数据与策略验证清单

> 配套 [[量化交易项目骨架]] 使用。这是一份**逐项可勾选**的执行清单。
>
> 用法：M1 跑完勾第一、二节；M2/M3 跑完勾第三、四节；引入任何第三方库前勾第五节。
> **任何一项打不了勾，就不要进入下一阶段**——回测漂亮的诱惑力非常大，清单是唯一的刹车。

---

## 一、数据门禁清单（对应 `DATA-PASS`）

- [ ] 每个标的都有**两个独立数据源**可比对；只有一个源时必须显式标注 `RECONCILE-SKIPPED`
- [ ] 规定好**源优先级**，并实现**自动降级**（不要依赖某一个源一定可用）
- [ ] 同一标的的**一次抓取只用一个源**（绝不拼接多源，避免口径混用）
- [ ] 双源对账用**不复权收盘价**（复权算法差异会伪装成"数据错误"）
- [ ] 对账超阈值时**显式报错**，不是静默通过
- [ ] 每个标的的抓取**元数据留档**：来源、时间、区间、行数、质检结论、对账结论
- [ ] 数据**新鲜度校验**：缓存过期必须重新抓取；抓取失败要报错，**不允许静默使用旧数据**
- [ ] 提供**离线模式**（纯缓存运行），保证断网时策略开发不被卡住
- [ ] 数据质检覆盖：负价/零价、高低价倒挂、重复日期、日期乱序、缺列、复权因子与价格不自洽
- [ ] **单位归一化**（见下方"坑清单"第 2 条），并在注释中标明单位
- [ ] 标的不同类型走**正确接口**（股票 / ETF / LOF / 可转债 / 指数往往各有一套接口）

## 二、防前视偏差清单（比任何策略都重要）

- [ ] **信号滞后**：用 t 时刻能拿到的信息做决策，在 t+1 执行（代码里至少有一处显式 `shift(1)`）
- [ ] **周线不要用数据商直供的周线**：无法判断周内极值出现的先后，应**由日线自合成**
- [ ] **未完成周期必须打标记**（如 `is_partial=True`），策略层强制丢弃
- [ ] **复权口径决策**（见下表），并保证不混用
- [ ] **时点测试**：截断 t 之后的数据，**所有已结束周期的特征值必须逐值不变**（写成单元测试，不是靠 review）
- [ ] **幸存者偏差**：没有历史时点的成分股/上市状态数据时，**禁止做选股类策略**；只做指数/ETF
- [ ] **未来函数自查**：任何"用当周/当日全量统计量"的因子（如周内排名、全期分位）都要检查是否越界

### 复权口径决策表

| 用途 | 用什么 | 原因 |
|---|---|---|
| 计算收益率、净值 | 后复权（hfq） | 历史值不随未来除权改写，缓存拼接安全 |
| 撮合成交价、涨跌停、最小报价单位 | 不复权 | 那才是真实成交价 |
| 两者关联 | 复权因子 = hfq/raw | 逐行校验一致性 |

> ⚠️ 常见误解：以为"前复权会把未来分红泄漏进历史"。**不对**——qfq 与 hfq 只相差一个常数倍，**区间收益率完全相同**。
> 选 hfq 的真实理由有两个：① qfq 的锚点随下载日期变化，**跨时间缓存拼接会产生虚假跳变**；
> ② 复权价**不能用于任何依赖绝对价格水平的计算**。

## 三、策略验证清单（对应 `SIM-PASS` / `OOS-PASS`）

- [ ] **引擎对账**：自研回测结果与独立实现（成熟库）对账，误差 < 1%
- [ ] **成本情景**：至少两档（乐观 / 保守），而不是假装知道精确成本
- [ ] **样本外**：留出一段**完全不参与任何参数选择**的数据，且只跑一次
- [ ] **基准对比**：每份报告都必须有买入持有基准，否则无法判断策略是否只是"随大流"
- [ ] **参数敏感性**：参数扰动 ±20% 后结论是否稳定（不稳定 = 过拟合信号）
- [ ] **失效条件**：写下至少两条"能打断当前逻辑链条"的事件
- [ ] **最坏情况**：明确最大可承受亏损，并有对应停机条件
- [ ] **退出方案**：策略失效后的后路（现金 / 切换标的 / 停止）
- [ ] **拥挤度 / 生命周期**：记录该策略处于"小众有效 / 扩散衰减 / 拥挤失效"哪个阶段
- [ ] **评估模块独立**：绩效评估与信号质量评估独立于回测库（避免"用同一把尺子量自己"）

## 四、风控门禁清单（硬代码，不接受"人工自觉"）

- [ ] 仓位上限、单标的上限、单日最大亏损、总回撤熔断**全部写在代码里**
- [ ] 风控拥有**一票否决权**，策略无权绕过
- [ ] 熔断触发后**必须停机**，不做"再等等看"的特例
- [ ] 开仓前三问做成**结构化必填字段**，缺项直接拒绝开仓
- [ ] 每次决策留下可回放的日志（信号、理由、否决记录）

## 五、第三方组件许可证检查清单（引入前必做）

- [ ] 查 `SPDX` 许可证（用 API 查仓库，不要只看博客推荐）
- [ ] 确认是 **MIT / BSD / Apache-2.0** 还是 **GPL / AGPL / 非商业 / Commons Clause**
- [ ] 检查**最近提交时间**（停更的库可能有隐藏兼容问题）
- [ ] 检查**仓库是否还存在**（有的"知名库"已被作者删除）
- [ ] 检查**Windows/目标平台是否有预编译 wheel**（避免被迫编译 C 扩展）
- [ ] 检查是否与当前依赖版本兼容（尤其 `numpy` / `pandas` 大版本）
- [ ] 若未来可能商业化，**现在就把"禁止商用"的组件降级为可选工具**，主线自研

## 六、真实坑清单（都是踩过的，不是想象出来的）

| # | 坑 | 具体现象 | 处理方式 |
|---|---|---|---|
| 1 | **不同标的类型接口不同** | 新浪股票接口对 ETF 直接报 JSONDecodeError | 按代码前缀分流到 ETF 专用接口 |
| 2 | **成交量单位不统一** | 东财给"手"，腾讯给"股"，相差 100 倍 | 适配器统一归一化为"股/份"，注释标明 |
| 3 | **复权价可能有内部基准** | 某源 2015-01-05 原始价 3.688，复权价 1.398（不等于原始价） | 不要假设"复权首日 == 原始首日" |
| 4 | **复权价精度有限** | 只保留 3 位小数，收益率带约 0.03% 舍入噪声 | 周线可接受；日线研究需重新评估 |
| 5 | **过期判定依赖系统时钟** | 单元测试结果随运行日期变化 | 给时间注入参数，让行为确定 |
| 6 | **批量任务被单个失败打断** | 一只标的失败导致整批退出，掩盖其他标的真实状态 | 收集失败、继续执行、最后汇总 |
| 7 | **静默失败比崩溃危险** | 接口挂了但回测照跑，结果错却无报错 | 所有异常路径都要显式报错或打标记 |
| 8 | **依赖版本漂移** | 某回测库在绘图库大版本升级后**导入即报错** | 锁定 `requirements.txt` 版本号 |
| 9 | **控制台编码与数据质量无关但会中断流程** | 打印 ✓/✗ 触发 UnicodeEncodeError 让整个流程崩掉 | 入口统一设置标准输出为 UTF-8 |
| 10 | **网络经代理后域名成片失效** | 数据源"时通时断"，同一域名先 5/5 成功后 10/10 失败 | 多源 + 缓存 + 离线模式 + 记录实测时间点 |
| 11 | **最低佣金被按“成交笔数”重复收** | 一笔订单分 3 次成交（部分成交）时收了 3 次最低 5 元；正确应为**按 order_id 累计**，总额不足最低值时才补差 | 佣金状态机按订单号记账（参见 rqalpha `CommissionMixin`）；**手算用例必须包含分批成交** |
| 12 | **费用/税率被写死成常量** | 印花税 2023-08-28 当天从 0.1% 降为 0.05%；写死单值会让跨该日的回测系统性偏差 | 时变参数一律“按日查表”，并在注释里写清生效日与来源 |
| 13 | **滚动统计用朴素平方和公式** | 数值大偏移、小方差时发生灾难性抵消，长序列标准差/波动率算错（vectorbt 2026-07 才修） | 用 Welford 等稳定算法；以 pandas 为 ground truth；**必须构造“大偏移小方差”对抗用例**（常规价格数据测不出来） |
| 14 | **“下单前资金预估”与“成交后实际扣费”用了同一套公式** | 预估是有状态（订单累计）还是不状态，二者结果不同，直接影响按资金比例下单能否成功 | 两个函数分开：预估允许偏高、不允许偏低；实际扣费走累计状态机 |

## 七、结论口径清单（怎么写报告才不算骗自己）

- [ ] 收益必须**同时给基准**（买入持有 / 指数）
- [ ] 必须标明**样本区间**与**样本外区间**，并分别给出结论
- [ ] 必须标明**成本假设**（几档情景，不是单一数字）
- [ ] 必须标明**最大回撤**，不能只报收益率
- [ ] 必须写**已知局限**与**未验证项**
- [ ] 不得使用"稳定盈利""确定性机会""必然"等词
