# 骨架：信源分级与信息流清单

> 用来回答两个问题：**这条信息我该信几分？** 和 **我每天/每月该看什么？**
>
> 配套：`政治经济研究骨架.md`（G0 溯源门禁用到这里的分级表）。

---

## 一、分级规则（不靠印象，靠三个问题）

对任何一条信息，依次问：

1. **它是原始记录，还是对原始记录的转述？**（转述一次掉一级）
2. **生产者是谁，有没有动机让这个数字/说法变成这样？**（有动机不代表错，但必须标注）
3. **我能追到一个可复现的原始链接/文件吗？**（追不到 → 只能是 L5）

| 等级 | 定义 | 典型例子 | 能不能进判断卡依据 |
|---|---|---|---|
| **L1 一手源** | 原始生产方发布的原文/原始数据 | 法律条文、部委通知、统计公报、企业公告 | ✅ 可以直接用 |
| **L2 学术源** | 有方法论约束、可被同行审查的研究 | 期刊论文、工作论文（NBER/arXiv）、复现包 | ✅ 但须过识别策略自检 |
| **L3 智库/研究机构** | 有研究团队但有立场/资助方 | BIS、World Bank、Bruegel、券商研究 | ⚠️ 须查资助方与立场，标 `SINGLE-SOURCE` |
| **L4 媒体** | 有编辑部与基本事实核查 | 财新、第一财经、经济观察报 | ⚠️ 只作**线索与时间锚**，数字须回 L1 |
| **L5 观点/线索** | 个人表达、无核查义务 | 公众号、播客、社交媒体、知乎 | ❌ 只进 Inbox 当线索 |

### 四类内容要分开判

同一条信息里往往混着四种东西，可信度判定标准完全不同：

| 类型 | 判定问题 | 典型风险 |
|---|---|---|
| **事实** | 有没有原始文件？ | 转述失真、断章取义 |
| **数据** | 口径是什么？谁算的？ | 口径混用、口径变更、修订 |
| **解释** | 用什么框架？谁的框架？ | 把解释当事实 |
| **预测** | 什么条件下成立？谁在打赌？ | 把预测当承诺，事后不追责 |

> 政经里 90% 的争论，是**把"解释"当成"事实"在吵**。写卡片时先给每句话贴类型标签。

### 2.3 企业/机构原始披露（扩展到微观时用）

### 复现资源（差分优先的抓手）

- **AEJ: Applied / AER 等期刊的 replication 包**：作者须公开数据与代码，可用来"跑通别人的结果再写自己的"
- **可复现性研究**：如 `larsvilhuber/aej-applied-replications-public`（对经济学可复现性的系统研究）
- 用法：**先跑通独立实现 → 生成差异清单 → 逐条归因**（我错/他错/口径不同/数据商不一致），再谈自己的结论

## 六、不可达与替代方案（2026-09-17 实测）

| 不可达 | 实测 | 替代 |
|---|---|---|
| Google Scholar | 000 ❌ | **OpenAlex / Semantic Scholar API**（免费、可脚本化，比 Scholar 更适合自动化） |
| SSRN / RePEc / IDEAS | 000 ❌ | NBER + OpenAlex + 期刊官网 |
| AEA（AER/JEL 站点） | 000 ❌ | Crossref 取元数据；正文找开放版本（OpenAlex 的 OA 链接） |
| FT 中文网 / The Economist | 000 ❌ | 财新/一财替代；或走代理；或用其邮件通讯 |
| Reuters / Bloomberg / WSJ 中文 | 000 ❌ | 财联社/证券时报的快讯可覆盖事件；深度需代理 |
| 知乎 | 403 ❌ | 不作证据源 |

## 七、检索通路（核验一个具体事实用什么）

| 场景 | 工具 | 实测 |
|---|---|---|
| 快速核验一个事实/找到原文 | `curl` + Bing / 百度 / 搜狗（免 API） | 200 ✅ |
| 找论文（可脚本化、可筛条件） | OpenAlex → Crossref → Semantic Scholar | 200 ✅ |
| 找预印本 | arXiv API（注意未评审） | 200 ✅ |
| 找中文社科论文 | 国家哲学社会科学文献中心（免费）→ CNKI（需权限） | 200 ✅ |
| 找官方数字 | 直接进对应部委站点，用站内搜索 | 见第二节 |
| 找历史长序列 | 统计局年鉴 / World Bank / FRED / BIS | 200 ✅ |

**检索纪律**：
- 搜到的东西**默认 L5**，直到你能点开原始来源。
- 引用时保存：URL + 访问日期 + （如可能）网页快照/PDF 原件到 `10-原始资料/`。
- 官方网页会改版和删文，**能存原件就存原件**。

### 连通性季度复测脚本（放到 `09-AI工作流/`）

```bash
# 用途：每季度重测一次信源可达性，把结果回填本文件
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/120"
for u in \
  "https://www.gov.cn/zhengce/zhengcewenjianku/" \
  "https://www.stats.gov.cn/sj/tjgb/ndtjgb/" \
  "https://www.mof.gov.cn/gkml/caizhengshuju/" \
  "http://www.pbc.gov.cn/zhengcehuobisi/125207/125227/125957/index.html" \
  "https://www.nber.org/papers" \
  "https://api.openalex.org/works?search=test&per_page=1" \
  "https://www.caixin.com" ; do
  printf "%-58s %s\n" "$(echo "$u" | cut -c1-58)" \
    "$(curl -s -m 10 -o /dev/null -w '%{http_code}' -L -A "$UA" "$u")"
done
```

## 八、信息流节奏（"日报"到底怎么读）

> 核心原则：**新闻不入库，只有"改变了某个数据/判断/时间线"的信息才入库。**
> 否则三个月后你会得到一个 500 篇笔记的资料垃圾场，而不是一个知识体系。

| 频率 | 时长 | 看什么 | 动作 | 产出 |
|---|---|---|---|---|
| **日** | 5–10 分 | 财联社/第一财经/财新 标题流 | 只判断一件事：**这改变了我的哪个卡片？** | 命中 → `99-Inbox/` 一条线索；否则不记 |
| **周** | 30 分 | 一周事件回顾 | 事件 → 机制连接；检查判断卡是否到期 | `00-MOC/时间轴.md`、判断卡更新 |
| **月** | 1–2 小时 | 统计局月度数据、央行金融数据、财政部月报 | 更新数据卡；对照上月判断 | 数据卡 + 判断卡回看 |
| **季** | 2–3 小时 | **《货币政策执行报告》**、智库季报 | 读长文本，做机制卡/立场卡 | 机制卡、争议地图 |
| **年** | 半天 | 政府工作报告、预算报告、统计公报 | 重估整个体系 | 总览 + 时间轴 + 判断复盘 |

### 入库三问（全"否"就不入库）

1. 它改变了我现有的某个数据/判断/时间线吗？
2. 我能追到原始来源吗？
3. 一年后回看它还有意义吗？

### 反模式（见到就停手）

| 反模式 | 症状 | 修正 |
|---|---|---|
| 收藏即学习 | Inbox 越长越安心 | 每周清空，清不掉就丢弃 |
| 转载当交叉 | "好多号都这么说" → 记 `CROSS-CHECKED` | 追到原始出处；同源转载 = 1 个来源 |
| 截图当证据 | 只有截图，无链接 | 截图 + URL + 日期，否则标 `UNVERIFIED` |
| 只看结论不看口径 | 记下数字不记口径 | 数据卡"口径"栏不许留空 |
| 追热点 | 每天都很忙，判断卡为零 | 判断卡数量是唯一 KPI |
