# 骨架：政治经济研究知识体系

> 一句话差别：**理工科骨架管"学会了没有"，这个骨架管"我是不是被说服了"。**
>
> 适用范围：广义政治经济学——政府与市场、制度与激励、财政与货币、国际政治经济、经济史。
> 不限于中国经济，也不限于经济学（政治学、社会学、经济史同构）。
>
> **本骨架不提供知识，只提供容器和门禁**。填什么内容由你决定。

---

## 0. 为什么不能直接套用《Obsidian-MOC-笔记体系》

理工科的卡片格式是：`tags / date / status` + 定义 + 我的理解 + 关联卡片。
这套格式在政经里**不够用**，因为两者的知识性质不同：

| 维度 | 理工（模电 / 微积分） | 政治经济 | 骨架必须新增的东西 |
|---|---|---|---|
| 真值 | 唯一、可复现 | 多解、不可复现，由历史与共识裁决 | 立场与对手字段 |
| 时效 | 麦克斯韦方程不过期 | **结论有保质期**："土地财政不可持续"这句话 2015 年和 2026 年含义完全不同 | 结论日期 + 复核日期 |
| 分歧 | 分歧 = 有人算错 | **分歧 = 结构**，学派/立场/利益位置是知识本身 | 争议地图 |
| 数据 | 测量误差 | **人为生产**：口径可改、可修订、可被策略性使用 | 口径 + 版本 + 修订史 |
| 验证 | 实验 / 仿真 | 只有自然实验 + 差分 + 事后检验 | 识别策略字段 |
| 核心工具 | 数学 + 仿真 | 因果推断 + 会计恒等式 + 历史对照 | 论文精读清单 |
| 学习终点 | 收敛（会做即结束） | **不收敛**（永远在途中） | 判断账本 |
| 典型失败 | 算错、接错线 | 叙事谬误、口径混用、相关性当因果、事后诸葛 | 失败模式清单 |

**结论**：理工卡片缺三样东西——**口径与版本、立场与对手、时效与证伪条件**。本骨架就是把这三样强行塞进卡片格式里。

## 1. 三条核心原则

1. **结论必须带日期，日期优先于正确。**
   政经里没有"永远正确"，只有"在某个时点、按某个口径、对某段数据成立"。任何不带日期的结论都视为未完成。

2. **分歧是结构，不是噪声。**
   看到两种相反说法时，第一反应不是"谁对"，而是"他们在比什么、用什么口径、代表谁"。把分歧记进 `00-MOC/争议地图.md`，比急着选边更重要。

3. **判断必须可证伪，而且必须下过注。**
   只写"我觉得……"没有价值。每一条判断都要写清：**什么证据会推翻它**、**什么时候回来看它**。
   这一条直接借自 `量化交易项目骨架`——量化最大的风险是"回测漂亮、实盘不同、还找不到原因"，政经最大的风险是"读了很多、观点很自信、从来没被打脸过"。

## 2. 结构：专题为单元，论证为主干，证据为附件

### 2.1 为什么推翻了第一版设计（实测记录）

第一版按**资料类型**分目录（概念/机制/数据/政策/论文/人物/案例）。试跑一个专题后发现问题，且有硬证据：

```
02-机制与框架   磁盘文件数=0   git跟踪数=0
```

**承担“逻辑链”职责的那个目录是空的；而且因为空，git 根本没把它推上去——远程仓库里它根本不存在。**

更深的问题：链条本来是
`分税制 → 地方缺口 → 转向土地 → 土地金融 → 房地产周期 → 出让金下滑 → 地方承压`，
按类型切目录，等于**把一条链切成 7 段扔进 7 个抽屉**。检索方便了，理解变难了。
而政经学习的目标是**理解**，不是检索。

**结论：目录的主干必须是“论证”，不是“资料类型”。**

### 2.2 两层结构（模板来源）

结构直接照一份经过编辑、经过读者验证的现成方案：《置身事内》的**上篇微观机制 / 下篇宏观现象**。
（目录已核实，来源：豆瓣书目页 `subject/35546622`，2026-09-17 抓取）

```
机制层（解释变量）：行为主体是谁 → 受什么约束 → 有什么激励 → 于是会怎么做
        ↓ 加总（一对多）
现象层（被解释对象）：这些行为加总后的可观测结果
        ↓
总结层：这对理解什么有用
```

三个要点（**第 3 点是第一版设计最大的错误**）：

1. **主语只有一个**：全书都在问“地方政府会怎么做、为什么”。一个专题也只该有一个主语。
2. **机制层是解释变量，现象层是被解释对象**：现象层每一节都要能回指机制层。
3. ⭐ **是“一对多”，不是单一纵链**：一套机制同时解释房价、债务、内外失衡。
   所以**现象层的每一节可以独立成立**（各自有数据），不依赖机制层某一环被完整证明。
   单一纵链的致命弱点恰恰是——**中间断一环，整条链作废**（第一版就断在中间）。

### 2.3 目录结构

```
政治经济/
├── README.md
├── AI会话规范.md
├── 00-MOC/                    导航与状态（**不放内容**）
│   ├── 总览.md
│   ├── 时间轴.md
│   ├── 争议地图.md
│   └── 待核实清单.md
├── 01-专题/              ⭐   主干：一个专题 = 一篇文章 + N 张论证卡
│   └── <专题名>/
│       ├── 00-主干.md           ← 专题唯一入口，从这里读
│       ├── M1-<节名>.md         机制层论证卡
│       ├── M2-<节名>.md
│       ├── P1-<节名>.md         现象层论证卡
│       └── ...
├── 02-证据/              ⭐   附件池：被引用，不参与主干
│   ├── 概念/                  定义与口径
│   ├── 数据/                  含 _raw/ 原始快照
│   ├── 政策原文/
│   ├── 论文/
│   └── 案例事件/
├── 03-立场与争议/         ⭐   谁说了什么 + 主要争论
├── 04-我的判断与复盘/     ⭐⭐  判断账本（本体系唯一 KPI）
├── 05-原始资料/               一手原文快照：只读不改
├── 06-AI工作流/               取数/检索脚本 + Prompt
├── 98-骨架库/
└── 99-Inbox/
```

**读法**：进入一个专题，**只从 `00-主干.md` 开始**。主干里某一节要求深挖时才点开对应论证卡；
论证卡里引用的数据/论文/政策，再到 `02-证据/` 里找。

**编号约定**：`M` = 机制层（Mechanism），`P` = 现象层（Phenomenon）。

**与理工骨架的区别**：理工按**知识依赖深度**编号（极限→导数→积分，一条收敛的链）；
政经按**论证单元**组织，没有收敛终点，所以关键是“每一个论证单元自己闭合”。

## 3. 论证卡（主干）与附件卡（证据）

> 统一约定：所有卡片的 frontmatter 必须含 `status` 与 `review`。
> 缺 `status` = 未完成；缺 `review` = 会过期的结论没设闹钟。

**两类卡片，地位不同：**

| | **论证卡** | **附件卡** |
|---|---|---|
| 位置 | `01-专题/<专题>/` | `02-证据/`、`03-立场与争议/` |
| 作用 | **推进论证**（主干） | **提供证据**（被引用） |
| 有无结论 | 有（④结语） | **没有** |
| 结构 | 问题→机制→证据→结语→反证 | 口径→内容→陷阱 |

> **为什么附件卡不该有结论**：数据是用来“支撑某一步推理”的，它自己不下结论。
> 第一版把附件卡当主干写，结果每张卡都像资料罗列——**没有“所以呢”**。

### 3.1 论证卡（本骨架的核心）

照《置身事内》“一节”的尺寸来写：问题 → 机制 → 证据 → 结语 → 反证。
**④结语是收口；缺了它，卡片就是资料堆。**

```markdown
---
tags: [论证, 机制, <主题>]
专题: <专题名>
编号: M2                      # M=机制层, P=现象层
status: UNVERIFIED           # 状态词见第 4 节
date: YYYY-MM-DD
review: YYYY-MM-DD
---

# M2 <这一节的标题>

## ① 这一节回答什么问题
（一句话。写成问句或“为什么X”。**答不出来，这节就不该存在**）

## ② 机制：为什么答案是这样
（**逻辑链本体**。一步一步写，每一步标注类型：
  【事实】可点开来源 ／【推断】由事实推出 ／【假设】未验证的前提）

## ③ 证据
| # | 证据 | 来源 | 级别 | 支持第几步 |
|---|---|---|---|---|

## ④ 结语：这一节证明了什么、没证明什么   ★收口★
（3–5 句。**必须同时写“没证明什么”**）

## ⑤ 反证与边界
（什么情况下不成立；谁反对；口径变了会怎样）

## ⑥ 附件
（链接到 02-证据/ 下的数据卡、论文卡、政策原文）
```

```markdown
# 1994 年分税制改革

## 事实层（只写能溯源的部分）
| 项 | 内容 | 来源 |
|---|---|---|
| 时间 | 1994-01-01 起施行 | 《国务院关于实行分税制财政管理体制的决定》（原文链接待补） |
| 核心内容 | 按税种划分中央/地方收入；增值税中央 75%、地方 25%；消费税归中央 | 同上 |
| 组织配套 | 分设国税、地税两套征收机构（2018 年合并） | 同上 |
| 出台背景 | 中央财政占比持续下降、"两个比重"过低 | 《置身事内》第 2 章（二手，需以原文复核） |

## 目标 vs 实际效果
| 宣称目标 | 实际效果 | 证据 |
|---|---|---|
| 提高中央财政收入比重 | 立竿见影（当年即显著上升） | 待以财政部/统计局原始数据核对 |
| 理顺中央地方关系 | 催生了后续的土地财政与地方融资平台 | 待引研究 |

## 争议 / 不同解释
- 一种解释：解决了中央财政危机，是后续高增长的前提
- 另一种解释：把事权与财权错配固定下来，是地方债问题的制度起点
- **争论点其实是**：这次改革的成本是否被推给了后来的地方政府？

## 时效
- 该政策的**长期影响**是否仍然成立？（2026 年看：土地出让逻辑已变）→ 复核日期前必须回看
```

**填写要点**：政策卡最容易写成"政策解读"。要守住两列：**宣称目标**和**实际效果**必须分开写，中间那条缝就是整个政治经济学的战场。

```markdown
| 项 | 林毅夫 | 张维迎 |
```

## 4. 证据门禁与状态词

借 `量化交易项目骨架` 的"门禁靠代码不靠自觉"思想，但改为**状态词 + 复核日期**驱动（因为政经无法自动化判定）。

### 4.1 状态词（frontmatter 的 `status`）

| 状态 | 含义 | 什么情况下能用 |
|---|---|---|
| `UNVERIFIED` | 未核实 | 默认状态。所有从二手渠道听来的说法 |
| `SINGLE-SOURCE` | 单一来源 | 找到一个来源，但无法交叉 |
| `CROSS-CHECKED` | 已交叉 | ≥2 个**相互独立**的来源一致（同一篇报道被多家转载 ≠ 2 个来源） |
| `FALSIFIED` | 已被推翻 | 找到反证。**保留卡片，不要删**，写明推翻证据 |
| `STALE` | 已过期 | 超过 `review` 日期未复核，由你或 AI 手动标记 |
| `RETRACTED` | 已撤回 | 自己发现之前的判断站不住，正式撤回并说明 |

> **对应关系**：这一套等价于硬件骨架的 `DOC-PASS / SIM-PASS / HW-PENDING / HW-PASS`。
> 核心精神相同：**没有证据支撑的状态词，一个字都不许升级**。

### 4.2 四级门禁（推进入库前逐项过）

| 门禁 | 检查什么 | 不通过怎么办 |
|---|---|---|
| **G0 溯源** | 每条事实能否点开一个原始来源？ | 进 `99-Inbox/`，同时登记到 `00-MOC/待核实清单.md` |
| **G1 口径** | 数字/概念的口径写清楚了吗？ | 标 `口径待定`，不许进数据卡正文 |
| **G2 交叉** | 重要结论有 ≥2 个独立来源吗？ | 保持 `SINGLE-SOURCE`，不许写进判断卡依据 |
| **G3 证伪** | 这条判断的推翻条件写了吗？ | 判断卡作废，不作为"已有判断" |

### 4.3 一切入库前的三条否决线（借自量化骨架的数据纪律）

1. **来源不可点开 → 不入库**（只进 Inbox 当线索）
2. **口径不明 → 不写数字**（宁可写"口径待确认"）
3. **只有一家说的重大结论 → 不进判断卡**（可以进 Inbox 观察）

## 5. 时效管理（理工骨架完全没有的一节）

政经知识的**过期不是例外，是常态**。给每类卡片设复核闹钟：

| 卡片类型 | 复核周期 | 理由 |
|---|---|---|
| 数据卡 | 月 / 季 | 官方数据按频率更新，超期即失真 |
| 政策卡（在行政策） | 6–12 个月 | 政策会被修订、被换口径、被新规覆盖 |
| 政策卡（历史政策） | 2–3 年 | 事实不变，但"它的影响"的评价会变 |
| 判断卡 | **下注时就定死** | 到期必须回看，允许空白但必须标记 |
| 论文卡 | 2–5 年 | 结论可能被复现、被反驳、被新数据推翻 |
| 立场卡 | 1–2 年 | 人物/机构立场会变 |
| 概念卡 | 5 年以上 | 概念最稳定，但口径会悄悄改 |

**操作**：`review` 字段过期 → 标 `STALE` → 要么复核续期，要么降级为"历史观点"。

## 6. 与量化项目的接口（复用 datasource 纪律）

你在 `D:\A_A_mylife\stock` 已经定下两条硬规矩：**只有 `datasource` 能联网**、**数据 raw/curated 分离**。
政治经济项目直接复用同一套纪律，但**不共用仓库**（数据口径与用途不同）：

| 项 | 约定 |
|---|---|
| 取数纪律 | 沿用"唯一联网模块 + 原始缓存（附 `_meta.json`）+ curated 分离" |
| 代码复用 | 可取数的脚本放 `06-AI工作流/`，**宏观专用**；不做跨项目 import，只复制范式 |
| 可复现 | 每个数据卡记录：取数脚本 + 运行日期 + 参数，保证能重跑 |
| 已知限制 | `data.stats.gov.cn/easyquery` 直连被 `UrlACL` 403（2026-09-17 实测），须走 akshare 或带 Referer 的请求；海关站点返回 412 反爬。**绕不过去就人工下载并记录日期** |

**注意**：不要为了"自动化"把时间花在爬虫上。政经的瓶颈是理解，不是取数。取数能自动就自动，不能自动就手工 + 记日期。

## 7. 裁剪建议与使用流程

### 裁剪（按投入程度）

| 规模 | 目录 | 卡片目标 | 复核节奏 |
|---|---|---|---|
| 泛读（每天 20 分钟） | `01-专题/` 的主干文章 + `04-我的判断与复盘/` + `99-Inbox/` | 判断卡 ≥1 张/周 | 月度清 Inbox |
| 专题研究（一个题目） | 全目录，重点 `01/03/04/05/07/08` | 30–80 张 | 双周复核 |
| 长期体系 | 全目录 | 200+ 张 | 月/季复核 |

**最低限度可用的版本**：只保留 `01-专题/<专题>/00-主干.md`、`00-MOC/争议地图.md`、`04-我的判断与复盘/`。
这三样就能跑起来，其余可以后补——**不要因为目录没建全就不开始**。

### 日常流程

| 频率 | 做什么 | 产出 |
|---|---|---|
| 日（5–10 分钟） | 扫标题（源清单见 `信源分级与信息流清单.md`） | 只有**改变了某个判断/数据/时间线**的才入库 |
| 周（30 分钟） | 事件→机制连接；更新判断卡到期项 | 时间轴 + 争议地图更新 |
| 月（1–2 小时） | 官方月度数据 → 更新数据卡；对照上月判断 | 数据卡 + 判断卡回看 |
| 季 | 《货币政策执行报告》等定期长文本 | 机制卡 / 立场卡 |
| 年 | 政府工作报告、预算报告、统计公报 | 时间轴 + 总览更新 |

### Git

与其它学科一致：本目录是独立仓库，每个知识里程碑一次 commit。
判断卡的**下注与复盘分开提交**（下注在先、复盘在后，历史不能改），提交信息示例：
`判断-2026-09-17-01 下注：地方财政矛盾转为存量付息` / `判断-2026-09-17-01 复盘：部分成立，归因口径错误`
