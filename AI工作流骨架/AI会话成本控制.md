# 骨架：AI 会话成本控制（会话卫生）

> **立规起因**：一次"给一门课建笔记体系 + 做教材作业 + 写工具"的会话，API 账单约 0.97（≈6.9 元）。
> 事后查会话日志发现：**97% 的 token 不是新读进来的，而是"把旧上下文重发一遍"**。
> 也就是说 —— **钱主要不是花在"任务本身"，而是花在"把多个任务塞进同一个会话"**。

---

## 一、先看账：钱到底花在哪（实测数据）

> 数据来源：本项目 2026-09-23 的会话日志（脚本：`工具-会话花费分析.py`）。
> 下面的数字会随会话继续而漂移，重点是**比例关系**，不是绝对值。

| 指标 | 数值（快照） | 说明 |
|------|------|------|
| API 调用次数 | **223** | 每次工具调用、每轮回复都算一次 |
| 上下文规模 | 11k → **394k** token（平均 227k） | **单调增长**：前面所有内容后面每次都要重发 |
| 新输入 token | 1,222,052 | 真正的"新信息"（图片、命令输出、文件内容） |
| 输出 token | 254,305（含思考 97k） | 写卡片/解答/文档 |
| **缓存重发 token** | **49,469,056** | 占总 token **97.1%** |
| 花费构成 | 输出 **31.5%** ｜ 新输入 **37.9%** ｜ 缓存重发 **30.6%** | 三段大致三分 |

**两条关键事实**：

1. 账单 ≈ **调用次数 × 上下文规模 × 单价**。上下文越长，后面每一句话越贵。
2. **"缓存过期后的全价重发"是隐形大坑**：该会话有 **3 次**这样的调用
   （31.8 万 / 35.7 万 / 37.1 万 token 新输入，缓存命中仅 9.6k），
   **三次吃掉 33% 的账单** —— 三次都发生在"会话闲置一段时间后继续"的时候。

## 二、五条硬规则

### 规则 1：一件事一个会话（最强杠杆）

把"建骨架 / 写卡片 / 做作业 / 写工具"拆成不同会话。每个会话从零上下文开始，
峰值上下文从 373k 降到 ~100k，后半程不再为"30 万字的历史"付费。

> 估算：同一批工作按现价约 **省 40%–60%**。

### 规则 2：长会话不打断；要打断就先收尾

- 会话闲置后继续，缓存可能已过期 → **一次全价重发**；
- 要么连续做完，要么**关掉重开**（重开时会话摘要/交接文档就是我们自己的缓存）。

**交接的最小动作**：把"当前状态 + 下一步 + 关键文件路径"写进项目里的 md，
换个会话直接读它，比继续用旧会话便宜得多。

### 规则 3：图片"先定位、后批量"，一遍看准

反面教材（本次踩过）：先读整页扫描图 → 估计比例裁剪 → 再读裁剪图核对 → 再修正 → 再读……
同页面反复读 3–4 次，最后读了 47 张图。

**正确做法**：
1. 先把整页渲染成**带百分比网格的一张图**（一次读图就看清所有题目的坐标）；
2. 用脚本按坐标**批量裁剪**；
3. 只对"最可能出错的那 1–2 张"做目视复核。

> 估算：图片读取次数可压到 **1/2 以下**，同时减少"改坐标-重跑"的循环。

### 规则 4：打进上下文的信息压到最小

| 反例（本次真实发生） | 正确做法 |
|--------------------|---------|
| 把教材整页文本打出来当搜索输出（单条 17,308 新输入） | 只打印 **页号 + 行号 + 关键词**；正文写临时文件按需读 |
| 打印整份 PDF 抽取结果 | 抽取结果写文件，只 grep 需要的那几行 |
| 一次读入几百行日志 | `tail -n` / `head -n` / 只输出结论行 |
| 大表格全量贴进对话 | 只贴决策所需的行，其余留在文件里 |

**一句话**：**上下文是计费的磁盘**，不是免费的工作台。

### 规则 5：文件一次写对，少"改-看-再改"

本次改了 21 次文件，每次编辑都在 300k+ 上下文下重新计费。
把同批改动**攒成一次 write/edit**，或先在草稿里定稿再落盘。

## 三、省钱不能省的底线（防走偏）

省钱的目的是**去掉重复劳动**，不是去掉验证。以下四件事**永远不许省**：

1. **数值验证 / 独立裁判**（手推结论必须与枚举/差分对撞）；
2. **来源核对**（页码、题号、版本必须实际提取核对，不许凭印象）；
3. **截图/关键产出的目视复核**（本次就是靠它发现"裁掉了 (b) 小问"）；
4. **git 提交与证据留痕**（否则下次要重新推导，反而更贵）。

> 判据：**验证次数可以少，验证证据不能缺。**

## 四、检查表

**开工前 30 秒**
- [ ] 这次会话只做一件事吗？（不是 → 拆会话，或先写下交接文档）
- [ ] 需要读图吗？（需要 → 先做网格图，别逐张试）
- [ ] 需要大段文本吗？（需要 → 写临时文件，只读需要的行）

**过程中（红线）**
- [ ] 上下文超过 ~150k 就该警觉：还能不能拆？（写完一个阶段就收尾）
- [ ] 单个命令输出超过 ~200 行 → 改成"只打印结论"
- [ ] 同一张图/同一段文本第二次读 → 停下来想想能不能存成文件
- [ ] 连续工作别超时闲置（缓存过期 = 全价重发）

**收尾**
- [ ] 把"当前状态 + 下一步 + 关键路径"写进项目 md（下次换会话直接读）
- [ ] 提交 git；报告花费构成（用第五节脚本）

## 五、自查账单：怎么看、怎么算

**日志位置**（每个项目目录一个文件夹）：

```
C:\Users\<用户名>\.pi\agent\sessions\<项目目录名>/*.jsonl
```

每次 API 调用的 `usage` 字段里有 `input / output / cacheRead / totalTokens / cost`。

**一条命令出报告**（脚本就在本目录）：

```powershell
Set-Location -LiteralPath "D:\A_lession\骨架库\AI工作流骨架"
python "工具-会话花费分析.py" --proj "D:\A_lession\数字信号处理"
```

输出：调用次数、上下文增长曲线、花费三段构成、最贵的 10 次调用、缓存失效次数（**就是那些"新输入巨大、缓存命中很小"的调用**）。

## 六、边界与例外

- **小任务不必强拆**：改一个错别字、查一个页码，单次会话最便宜；
- **探索性任务**（不知道要干什么）难以预先分阶段 → 先花 1 个会话把"未知"变成"待办清单"，
  再按清单分阶段执行；
- **跨阶段共享的"事实底座"**（页码表、术语表、目录结构）应落在仓库 md 里，
  它既是笔记，也是**下次会话的免费缓存**。
